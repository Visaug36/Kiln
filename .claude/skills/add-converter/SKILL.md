# Adding a conversion pair

Three steps, three files. No component changes, ever — the interface reads the
registry and renders whatever is there.

**1. Write the engine** at `lib/registry/converters/<from>-to-<to>.ts`, exporting
`convert(input: File): Promise<ConversionResult>`. Every heavy dependency is
named inside the function, behind `await import()`. Nothing at module scope.

**2. Declare the pair** in `lib/registry/index.ts` — `from`, `to`, `fidelity`,
and a `caveat` if it is not `exact`.

**3. Wire the engine** in `lib/registry/engines.ts` as `'<from>><to>': () =>
import(...)`. Steps 2 and 3 are separate files so the page never reaches an
`import()`; they cannot drift silently, because `lib/registry/index.test.ts`
fails if a declared pair has no engine or an engine has no declared pair.

If the format is new to Kiln, add it to the `Format` union in `types.ts`, to
`FORMATS` (the canonical display order), and to `MIME` in `shared.ts`.

## Choosing a fidelity

- **`exact`** — nothing is lost. The bytes pass through, or the round trip is
  provably lossless. Say this only if you would stake a test on it.
- **`good`** — structure survives, presentation may shift. Headings stay
  headings; the font does not.
- **`lossy`** — something the user cares about is dropped.

**A `lossy` pair must carry a `caveat`,** and a test enforces it. Name what is
lost in the user's terms ("Tables and images are dropped"), not the library's.

Fidelity is a promise about the pair. `warnings` is a report about one file:
**anything an engine actually discarded goes in `warnings`**, every time. Silent
loss is a bug, not a simplification.

## Tests and fixtures

`lib/registry/converters/converters.test.ts` is table-driven over `converters`,
so a new pair is exercised the moment it is declared — non-empty output, right
MIME type, right extension, real magic bytes, and a readable sentence on a
corrupt file. That is the floor, not the test. Add an assertion that the
**content** survived, next to the others in that file.

Fixtures live in `test/fixtures/` and are generated by `scripts/make-fixtures.mjs`
(`pnpm fixtures`) from Kiln's own writers, so a reader that only appears to work
cannot pass. Load one with `fixture('sample.docx')`; every generated fixture
contains `MARKER`.

## Worked example: RTF → PDF

```ts
// lib/registry/converters/rtf-to-pdf.ts
import type { ConversionResult } from '@/lib/registry/types';
import { outputFile, readText } from '@/lib/registry/shared';
import { parseRtf } from './_rtf';

export async function convert(input: File): Promise<ConversionResult> {
  const { blocksToPdf } = await import('./_blocks-to-pdf'); // heavy: pdfmake
  const paragraphs = parseRtf(await readText(input));

  return {
    files: [outputFile(input.name, 'pdf', await blocksToPdf(paragraphs))],
    warnings: ['Tables and images in the source were dropped.'],
  };
}
```

```ts
// lib/registry/index.ts
{
  from: 'rtf',
  to: 'pdf',
  fidelity: 'lossy',
  caveat:
    'Structure is guessed from the font sizes RTF records, and the page is laid out again from scratch.',
},
```

```ts
// lib/registry/engines.ts
'rtf>pdf': () => import('./converters/rtf-to-pdf').then((m) => m.convert),
```

`.pdf` now appears in the picker for any dropped `.rtf`, the caveat shows before
conversion starts, and no component was edited.

Then run `pnpm verify:browser`, which drives the real UI in Chromium. Several
bugs have reached that script and nothing earlier.

The README's "The converter registry" section has the full contract, the exports
table, and the conventions engines follow. Read it rather than guessing; do not
restate it here.
