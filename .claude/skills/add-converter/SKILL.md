# Adding a conversion pair

Three steps, three files, no component changes. The interface reads the registry
and renders whatever is there, so a pair appears in the picker the moment it is
declared.

**1. Write the engine** at `lib/registry/converters/<from>-to-<to>.ts`, exporting
`convert(input: File): Promise<ConversionResult>`. Every heavy dependency is
named inside the function, behind `await import()`. Nothing at module scope.

**2. Declare the pair** in `lib/registry/index.ts` — `from`, `to`, `fidelity`,
and a `caveat` unless it is `exact`.

**3. Wire the engine** in `lib/registry/engines.ts`:
`'<from>><to>': () => import('./converters/<from>-to-<to>').then((m) => m.convert)`.

Steps 2 and 3 live in separate files so the **page never reaches an `import()`**
— one in a module the page imports makes the bundler emit a chunk for every
engine. They cannot drift silently: `lib/registry/index.test.ts` fails if a
declared pair has no engine, or an engine has no declared pair.

If the format is new to Kiln, also add it to the `Format` union in `types.ts`, to
`FORMATS` (the canonical display order), to `MIME` in `shared.ts`, to `FOOTPRINT`
in `lib/files/capacity.ts`, and to detection in `lib/files/detect.ts`.

## Choosing a fidelity

- **`exact`** — nothing is lost. The bytes pass through, or the round trip is
  provably lossless. Claim it only if you would stake a test on it.
- **`good`** — structure survives, presentation may shift. Headings stay
  headings; the font does not.
- **`lossy`** — something the user cares about is dropped.

**A `lossy` pair must carry a `caveat`, and a test enforces it.** Name what is
lost in the user's terms — "Tables and images are dropped" — not the library's.

Fidelity is a promise about the pair; `warnings` is a report about one file.
**Anything an engine actually discarded goes in `warnings`,** every time. Silent
loss is the worst failure Kiln has.

## Tests and fixtures

`converters.test.ts` is table-driven over `converters`, so a new pair is
exercised the moment it is declared: non-empty output, right MIME type, right
extension, real magic bytes, a readable sentence on a corrupt file. **That is the
floor, not the test.** Add an assertion that the content actually survived, and
run the `probe` skill's checklist against the new pair.

Fixtures live in `test/fixtures/` and are generated by `scripts/make-fixtures.mjs`
(`pnpm fixtures`) from Kiln's own writers, so a reader that only appears to work
cannot pass.

## Before you call it done

```
pnpm test && pnpm lint && pnpm typecheck && pnpm build && pnpm verify:browser
```

`verify:browser` drives the real UI in Chromium. Several bugs have reached that
script and nothing earlier.

## Reference
